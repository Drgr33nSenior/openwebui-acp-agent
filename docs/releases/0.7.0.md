# OpenMettle ACP 0.7.0

An independent coding agent for JetBrains and other compatible ACP clients,
using your Open WebUI installation.
This release includes the changes merged since 0.6.0. It is the first release
under the OpenMettle ACP name and the `openmettle-acp` package.

## Upgrade

- The package is now `openmettle-acp` and the release asset is
  `openmettle-acp-0.7.0.tgz`. The primary command is `openmettle-acp`;
  `openwebui-acp-agent` remains as an alias.
- After installing, the client registration's entrypoint becomes
  `node_modules/openmettle-acp/dist/cli.js`. Keep the registration's existing
  name and update only its command path.
- Configuration, saved sessions, trust, the OS credential-store entry,
  `OPENWEBUI_ACP_HOME`, `OPENWEBUI_API_KEY` and the administrator policy path are
  unchanged. Nothing is migrated, and no new sign-in is needed.
- Rebuild the optional browser container to get its new confined endpoint.

See [the rename and upgrade notes](../migration.md#openmettle-rename).

## Editing and files

- `write_file` takes `{path, content}`. The model no longer retypes the current
  file. An existing file is replaced only when the agent has read it in this
  session and it has not changed since; otherwise the call is refused before
  approval with a request to read it first. Older `{path, before, after}` calls
  still work.
- `write_file` refuses to rewrite an existing file larger than 8 KB and asks for
  `edit_file` instead, so a whole-file rewrite is not cut off by the output limit.
  New files and small files are unaffected.
- `edit_file` on a missing file, and a write into a missing folder, explain what
  to do instead of returning a raw `ENOENT` error. Placeholders left by context
  clearing are labelled as not file text, and a copied placeholder is refused.

## Visual checks

- `view_image` lets the model look at PNG, JPEG, GIF or WebP screenshots in the
  workspace, up to 1 MB and 1280×1280. Only the latest images stay in context,
  and saved sessions keep the path, size and hash rather than the image. The
  `viewImage` setting (`auto`, `on`, `off`) controls the tool; `auto` respects a
  model's explicit `vision: false` in Open WebUI.
- For games, GUIs and web UIs, the definition of done asks for real input,
  screenshots viewed with `view_image` and a final message saying what was seen.
  See [play-testing interactive apps](../runtime-verification.md#play-testing-interactive-apps).

## Long turns, reasoning and output limits

- The default `rounds` limit rises from 40 to 100 model rounds per turn, and the
  maximum from 100 to 250. The 64 tool-call budget is unchanged. Set `rounds`
  in the configuration to lower it.
- At Max (`xhigh`), the output cap no longer exceeds the server's advertised
  output limit, which previously could make the first request fail. When the
  server declares an output limit for the Max level (`maxOutputTokens` on its
  `xhigh` entry in `supportedReasoningEfforts`), that limit is used, within half
  the context window, and reserved when sizing input. Without it the cap is the
  advertised `max_output_tokens`, or 32,768 when none is advertised. Runtime
  guidance states the allowance each request actually gets.
- A reply whose thinking used the whole output limit before any text or tool call
  says so in its notice. It is re-asked once at the same reasoning level and cap,
  with an instruction to keep reasoning brief. No tools from that reply run.
- Structured reasoning (`reasoning_content`, or its `reasoning` alias) is kept
  apart from the visible reply. It is sent back in later requests only for
  models whose Open WebUI model entry declares
  `provider_capabilities.reasoning_replay` as `reasoning_content`; requests for
  other models are unchanged. Exports and compaction summaries omit it.
- Long reasoning from a model without that declaration no longer inflates the
  context estimate and stops the next tool round.
- Error messages add a retry delay only when the server sends a positive
  `Retry-After`.

## Commands and sandbox

- Unsandboxed commands and background jobs end when the agent process ends,
  including when the client kills it or it crashes. One supervisor process per
  agent also enforces command timeouts while the agent is stalled. See
  [commands and background jobs](../sessions.md#commands-and-background-jobs).
- A sandboxed connection to a local server started by the session's own
  unsandboxed background job, or its static preview, no longer prompts. Other
  loopback destinations offer **Allow localhost (any port) for this session**.
  Reserved service ports and the agent's own Open WebUI and MCP ports still
  prompt each time. Administrators can disable both shortcuts with
  `allowLoopbackShortcuts: false`. See
  [local development servers](../sandbox.md#local-development-servers).
- On macOS, the sandbox broker keeps its internal socket path within the
  platform's length limit, so sandboxed commands no longer fail to start when
  the temporary directory path is long.

## Clients and browser

- T3 Code desktop (Beta 0.1.6 on macOS) can connect its client-supplied MCP
  bridge. Workspace and connection approvals and administrator checks still
  apply. See [T3 Code](../t3.md).
- The optional browser wrapper serves `/mcp/confined` next to `/mcp`. A session
  opened there loads only plain-HTTP origins that the MCP client opened; links,
  redirects, scripts, frames and history cannot reach another origin. Ordinary
  sessions are unchanged. See [confined sessions](../browser.md#confined-sessions).

## Testing and benchmark harness

- A long-session benchmark kit and a browser-game benchmark with hidden checks,
  screenshots and reporting are included as opt-in manual tools. Their offline
  self-tests run with `npm test`; they are not part of the installed agent's
  behavior. See [long-session benchmark](../verification.md#long-session-benchmark).
- Test reliability fixes cover pid-file races, fixture servers that outlived
  their session, and cleanup ordering in the game qualification tests.

## Shipped in 0.6.0 but not previously noted

This change was included in 0.6.0 but missing from its release notes:

- Common tool misuse is recovered without a wasted round: `search_text` accepts
  a single file as `path`; `read_file` with an offset past the end returns the
  last page with a note; `run_command` refuses a command line in `executable`
  and suggests the corrected `executable` and `args`.

## Install

Use Node.js 26 LTS and npm on macOS or Linux:

```sh
npm install --global https://github.com/OpenMettle/openmettle-acp/releases/download/v0.7.0/openmettle-acp-0.7.0.tgz
```

Use the package attached to the GitHub release; `SHA256SUMS` verifies it.
No npm account is needed. Keep the previous installation for rollback and
reconnect the IDE after updating its launch path. See [setup](../../README.md),
[session controls](../sessions.md), [tools](../tools.md) and
[upgrade and rollback](../migration.md).

## Scope and verification

The protocol remains stable ACP v1. Native Windows is unsupported. Browser MCP
and Open WebUI server tasks remain optional and separately approved. ACP registry
inclusion and npm publication are separate from this GitHub release.

The [verification record](../verification.md) distinguishes automated tests from
live backend and IDE acceptance. Client UI support and provider behavior still
require testing with the versions in use.
