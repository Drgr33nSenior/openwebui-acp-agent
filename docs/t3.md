# T3 Code

Add the installed agent through **Settings → Providers → Add provider → Show
more → Local ACP command**. Use an absolute Node executable and two arguments:
the installed `dist/cli.js` path, followed by `acp`. Leave environment overrides
empty; the agent manages its own configuration and OS credential-store entry.
Models and supported session options come from the agent. T3 runs it on the
machine hosting the T3 server.

## Desktop MCP compatibility

T3 Code Beta 0.1.6 on macOS supplies a `t3-code` MCP stdio descriptor. Its
Electron command runs `app.asar/apps/server/dist/bin.mjs acp-mcp-bridge` with
`ELECTRON_RUN_AS_NODE`, `T3_ACP_MCP_ENDPOINT` and `T3_ACP_MCP_AUTHORIZATION`.
The bundled bridge forwards JSON-RPC to the endpoint with the given authorization
header. Source inspection covered `acpMcpContext`, `sessionMcpServers` and
`AcpMcpStdioBridge` in that installed version. The generic ACP integration chooses
stdio; its HTTP alternative is currently enabled only for a different provider.

The agent maps this exact client-supplied desktop descriptor to Streamable HTTP.
It accepts only a loopback HTTP endpoint with an explicit port and `/mcp` path,
without URL credentials, query or fragment. Unknown descriptors keep their normal
transport. Explicit user MCP configuration does not gain this mapping.

Workspace and connection approvals still precede connection. Administrator checks
apply to both the original descriptor and the HTTP destination. Tools execute
outside the agent's OS sandbox and retain the existing remote-tool approvals;
they receive no IDE-diagnostic exemption. The adapter does not run the desktop
process unsandboxed. Authentication remains separate from the Open WebUI key.

The authorization value remains redacted. The verified public
`ELECTRON_RUN_AS_NODE=1` flag is excluded from secret values so that every digit
`1` in status output is not replaced. Invalid descriptors remain fully redacted.

This adapter was required by the first local 0.6.0 trial: `/status` worked, while
the first inference prompt failed during the second MCP server's connection.
Live results for the patched version are recorded separately from fake-server
tests. Linux T3 and other desktop versions have not been checked.

T3's background model probe uses its server working directory. If that is the
home directory, the agent refuses it as a workspace. A session in a real project
publishes models and controls through T3's live configuration path, as in the
local smoke test. A probe warning after restarting T3 may therefore remain until
a project session opens. The integration does not grant home-directory access.
